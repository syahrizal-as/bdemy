Sesi 3.1: Melakukan Debugging (J.620100.025.02)

Debugging bukan hanya mencari error, tapi memahami aliran logika program Anda.

Teknik Dump & Die (dd)

Hentikan waktu! Bedah variabel di titik manapun untuk melihat isinya.

// Bedah Request & User sekaligus
dd($request->all(), auth()->user());

Membaca Stack Trace

Jangan panik saat melihat layar merah! Pelajari cara membaca urutan pemanggilan fungsi (Stack) untuk menemukan "Epicenter" dari sebuah error.

Logic vs Syntax Error

Syntax error mudah ditemukan (program berhenti), namun **Logic Error** (data tidak sesuai ekspektasi) membutuhkan ketelitian tinggi dan penggunaan `dd()` yang strategis.

Laravel Telescope

Dashboard monitoring untuk memantau Query Database yang lambat, Request, hingga Mail secara visual.

composer require laravel/telescope --dev
php artisan telescope:install
php artisan migrate

Error Handling & DB Transactions

Menjamin integritas data. Jika terjadi error di tengah proses, semua perubahan database akan dibatalkan (*Rollback*).

use Illuminate\Support\Facades\DB;

DB::beginTransaction();
try {
    $product->save();
    // Simulasikan error di sini
    DB::commit(); // Simpan permanen
} catch (\Exception $e) {
    DB::rollBack(); // Kembalikan data seperti semula
    Log::error("Gagal simpan data: " . $e->getMessage());
}

Advanced Tinker

Gunakan Tinker untuk mensimulasikan input tanpa Form. Sangat berguna untuk mengetes kueri Eloquent yang kompleks secara instan.

php artisan tinker

Custom Logging

Gunakan `Log::debug()` untuk mencatat variabel saat aplikasi berjalan di background tanpa menghentikan eksekusi.

Log::channel('single')->info('User Login: ', ['id' => $user->id]);

Self-Documenting Code

Tulis kode yang "berbicara". Jika nama variabel Anda sudah jelas, komentar panjang lebar tidak lagi diperlukan.

$expiredProducts = Product::where('exp_date', '<', now())->get();

Manajemen Versi dengan Git

Track Record History

Git menyimpan jejak setiap perubahan kode secara permanen. Jika suatu saat rilis terbaru mengalami kerusakan fatal (sistem down), kita bisa mengembalikan kode ke kondisi sehat sebelumnya (rollback) dalam hitungan detik.

Git Workflow Dasar

git add . - Memasukkan perubahan ke tahap *staging*.
git commit -m "Pesan" - Menyimpan *snapshot* kode beserta deskripsinya.
git push - Mengirimkan *snapshot* ke repositori jarak jauh (GitHub/GitLab).

Git Branching

Memungkinkan pengembang mengisolasi eksperimen fitur baru ke jalurnya sendiri tanpa mengganggu kode sumber utama (main/master). Jika eksperimen tersebut gagal, branch tersebut dapat dibuang tanpa memberikan efek samping pada aplikasi.

Publikasi ke GitHub (Cloud Repository)

Git adalah alat lokal di komputer Anda, sedangkan GitHub adalah platform cloud terpopuler untuk menyimpan source code, memamerkan portofolio, dan berkolaborasi jarak jauh. Meng-upload proyek (LaraStock) ke GitHub adalah langkah wajib bagi seorang Web Developer agar karya Anda bisa dinilai oleh calon perekrut (HRD).
